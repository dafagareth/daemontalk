Sebagian besar tutorial Go berhenti di "cara mencetak Hello World", padahal masalah nyata baru muncul setelah itu: kapan pakai slice bukan array, kenapa `error` bukan `exception`, dan kenapa method dengan pointer receiver bisa mengubah perilaku program secara diam-diam. Sepuluh konsep berikut adalah fondasi yang, kalau dilewatkan, akan terus muncul sebagai bug di kemudian hari.

---

## 1. Tipe Data Statis dan Deklarasi Variabel

Go adalah bahasa *statically typed* — tipe ditentukan saat kompilasi, bukan saat program berjalan. Ini konsekuensinya lebih jauh dari sekadar "harus tulis tipe": Go **tidak melakukan konversi implisit**, bahkan antar tipe numerik.

```go
var suhu float64 = 36.6
var jumlah int = 3

// suhu * jumlah akan gagal compile — mismatched types
hasil := suhu * float64(jumlah) // wajib konversi eksplisit
```

Dua cara deklarasi yang perlu dibedakan:

- `var nama tipe = nilai` --> dipakai di level package atau saat butuh zero value eksplisit.
- `nama := nilai` --> *short declaration*, hanya berlaku di dalam fungsi.

Kesalahan umum pemula: memakai `:=` di luar fungsi. Go tidak mengizinkannya, dan pesan error yang muncul sering membingungkan karena bukan soal tipe, melainkan soal scope.

---

## 2. Struktur Kontrol: Hanya Ada `for`

Go sengaja tidak punya `while` atau `do-while`. Semua bentuk perulangan memakai `for`, dengan tiga variasi:

```go
for i := 0; i < 5; i++ { }   // bentuk klasik

for kondisi { }              // menggantikan while

for {                        // infinite loop, keluar via break
    break
}
```

Yang lebih sering menjebak pemula adalah `range` pada slice — variabel iterasi adalah **salinan**, bukan referensi ke elemen asli:

```go
angka := []int{1, 2, 3}
for _, v := range angka {
    v *= 2 // tidak mengubah isi slice angka
}
```

Untuk mengubah isi slice, harus lewat index: `angka[i] *= 2`.

---

## 3. Fungsi dengan Multiple Return Values

Go tidak punya *tuple* asli, tapi fungsi bisa mengembalikan lebih dari satu nilai — dan ini bukan fitur kosmetik, melainkan dasar dari idiom penanganan error di seluruh ekosistem Go.

```go
func bagi(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("pembagi tidak boleh nol")
    }
    return a / b, nil
}

hasil, err := bagi(10, 0)
if err != nil {
    log.Fatal(err)
}
```

Pola `nilai, err := fungsi()` akan muncul ratusan kali dalam kode Go production. Membiasakan diri membaca pola ini sejak awal jauh lebih penting daripada menghafal syntax lain.

---

## 4. Array vs Slice — Sumber Bug Paling Umum

Array di Go punya ukuran tetap dan **jarang dipakai langsung** di kode production. Slice adalah struktur dinamis yang membungkus array di baliknya, dan pemahaman soal *underlying array* ini krusial:

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]     // b berbagi underlying array yang sama dengan a
b[0] = 99       // mengubah a[1] juga
```

Tabel berikut merangkum perbedaan mendasarnya:

| Aspek | Array | Slice |
| :--- | :--- | :--- |
| Ukuran | Tetap, bagian dari tipe (`[5]int`) | Dinamis |
| Deklarasi umum | `var a [5]int` | `a := []int{}` atau `make([]int, 0)` |
| Passing ke fungsi | Disalin penuh (copy value) | Header disalin, data dibagi (shared) |
| Penggunaan realistis | Jarang | Sangat umum |

`append()` bisa membuat *underlying array* baru jika kapasitas tidak cukup — inilah alasan slice hasil `append` kadang tidak lagi berbagi memori dengan slice aslinya. Ini salah satu perilaku yang wajib dipahami sebelum menulis kode yang memodifikasi slice secara bersamaan (concurrent).

## 5. Map dan Idiom "Comma, OK"

Map adalah struktur key-value bawaan. Masalah yang sering muncul pada pemula: membedakan antara *key tidak ada* dan *key ada dengan zero value*.

```go
stok := map[string]int{"apel": 10}

jumlah := stok["jeruk"] // 0, tapi bukan berarti "jeruk" ada dengan stok 0

jumlah, ada := stok["jeruk"]
if !ada {
    fmt.Println("jeruk tidak ditemukan di stok")
}
```

Idiom `nilai, ok := map[key]` ini sama pentingnya dengan pola error handling di poin sebelumnya — bentuknya konsisten dipakai juga untuk type assertion dan channel.

## 6. Struct dan Method: Value Receiver vs Pointer Receiver

Go tidak punya class, tapi punya `struct` untuk data dan `method` untuk perilaku. Perbedaan value receiver dan pointer receiver adalah salah satu konsep yang paling sering disepelekan pemula, padahal berdampak langsung ke behavior program:

```go
type Akun struct {
    Saldo int
}

func (a Akun) TambahValue(n int) { a.Saldo += n }   // tidak mengubah akun asli
func (a *Akun) TambahPointer(n int) { a.Saldo += n } // mengubah akun asli

akun := Akun{Saldo: 100}
akun.TambahValue(50)
fmt.Println(akun.Saldo)   // masih 100

akun.TambahPointer(50)
fmt.Println(akun.Saldo)   // jadi 150
```

Aturan praktis: kalau method perlu mengubah state struct, atau struct-nya besar (menghindari copy berulang), pakai pointer receiver.

## 7. Interface: Kepatuhan Implisit

Go tidak punya keyword `implements`. Sebuah tipe otomatis memenuhi interface selama ia memiliki semua method yang dibutuhkan — tanpa deklarasi eksplisit apa pun.

```go
type Penulis interface {
    Tulis(data string) error
}

type FileLogger struct{}
func (f FileLogger) Tulis(data string) error {
    fmt.Println("menulis ke file:", data)
    return nil
}

var p Penulis = FileLogger{} // valid, tanpa deklarasi apa pun
```

Pendekatan ini disebut *structural typing*, dan merupakan alasan kenapa banyak paket standar Go — seperti `io.Writer` — bisa dipakai lintas library tanpa dependensi eksplisit satu sama lain.

## 8. Error Sebagai Nilai, Bukan Exception

Go tidak punya `try/catch`. Error diperlakukan sebagai nilai biasa bertipe `error`, dan **wajib dicek secara eksplisit** setiap kali muncul:

```go
data, err := os.ReadFile("config.json")
if err != nil {
    return fmt.Errorf("gagal membaca config: %w", err)
}
```

`panic`/`recover` memang ada, tapi bukan pengganti error handling — keduanya dipakai untuk kondisi yang benar-benar tidak wajar (misalnya index di luar batas), bukan untuk alur logika normal seperti "file tidak ditemukan".

---

## 9. Goroutine dan Channel: Dasar Concurrency

Ini bagian yang membedakan Go dari kebanyakan bahasa lain di level bahasa itu sendiri, bukan library tambahan.

```go
ch := make(chan string)

go func() {
    ch <- "selesai diproses"
}()

pesan := <-ch
fmt.Println(pesan)
```

`go` menjalankan fungsi sebagai goroutine — unit eksekusi ringan yang dikelola runtime Go, bukan OS thread langsung. `channel` dipakai untuk komunikasi antar goroutine secara aman tanpa lock manual. Prinsip yang sering dikutip dari dokumentasi Go: *jangan berkomunikasi dengan berbagi memori, tapi bagikan memori dengan berkomunikasi*.

Untuk pemula, cukup pahami pola dasar ini dulu sebelum masuk ke `sync.WaitGroup`, `select`, atau `context` — mencoba menguasai semuanya sekaligus biasanya berujung bingung, bukan paham.

---

## 10. Package dan Modul (`go.mod`)

Setiap file Go adalah bagian dari sebuah package, dan `package main` khusus menandai entry point program yang bisa dikompilasi jadi binary. Sejak Go 1.11, manajemen dependensi memakai Go Modules:

```bash
go mod init namamodul
go get github.com/some/library
```

File `go.mod` menyimpan nama modul dan versi dependensi. Pemula sering melewatkan bagian ini karena tutorial pendek biasanya cuma satu file — tapi begitu proyek melibatkan lebih dari satu package atau library eksternal, memahami struktur modul jadi wajib, bukan opsional.

```faq
Q: Apakah wajib paham goroutine dan channel sebelum belajar hal lain?
A: Tidak wajib di awal. Kuasai dulu poin 1–8 sampai terbiasa, karena goroutine yang dipakai di atas fondasi yang belum kuat justru sering menghasilkan bug yang sulit dilacak seperti race condition.

Q: Kenapa Go tidak punya exception seperti bahasa lain?
A: Ini keputusan desain yang disengaja. Tim Go menganggap error sebagai bagian normal dari alur program, bukan kondisi luar biasa — sehingga error harus terlihat jelas di setiap pemanggilan fungsi, bukan tersembunyi lewat mekanisme try/catch.
```
